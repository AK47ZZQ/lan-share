# LAN Share App · 需求规格（APP-REQUIREMENTS v0.1）

> 家庭网盘移动客户端。平台：Android + iOS（Flutter 跨端）。
> 服务端为现有 LAN Share v3.6+（本仓库 `app/`），本 App 是其原生移动入口。
> 状态：需求评审稿（2026-09-01）。配套设计见 `docs/DESIGN-v3/APP-DESIGN.md`。

## 1. 背景与目标

LAN Share 网页版已覆盖家庭场景核心需求，但"手机相册自动备份"与"系统级分享接收"
依赖平台后台能力，网页/PWA 无法实现。本 App 的目标：

1. **无感备份**：家人的手机照片在连家庭 Wi-Fi 时自动、安全地进入网盘，零手工操作
2. **随手取用**：手机上直接浏览/搜索/下载网盘文件与照片
3. **系统级入口**：任何 App 的"分享"都能存进网盘；网盘内容一键生成对外分享

**非目标（现阶段明确不做）**：在线编辑文档、多人实时协作、视频转码播放（走系统播放器）、
第三方云盘互通。

## 2. 用户与角色

| 角色 | 描述 | App 内权限 |
|------|------|-----------|
| 家庭成员 | admin/member，受邀注册 | 全部功能（数据按服务端授权矩阵过滤） |
| 访客 guest | 只读成员 | 浏览/下载，无备份与分享创建 |
| 未登录 | 首次启动 | 仅登录页；服务器地址预填上次使用 |

## 3. 用户故事（核心场景）

- US-1 我拍完照片，回家连上 Wi-Fi，照片自动出现在网盘，我不需要做任何事
- US-2 我在群里收到一个文件，系统分享给 LAN Share，文件进入我的 incoming
- US-3 出门在外想给朋友发一个网盘里的视频，App 内创建带提取码的分享链接
- US-4 老婆发我一个定向分享，App 弹通知，我点开直接取件
- US-5 我换了手机，登录同一账号，自动备份从新设备继续（旧设备可在网页端吊销）

## 4. 功能需求

优先级：P0 = 首版必须有；P1 = 首版尽量；P2 = 后续版本。

### FR-1 认证与设备（P0）
- 账号密码登录；启用 TOTP 的账号追加动态码输入（对应现有 `/api/login`、`/api/login/totp`）
- 登录成功 → 获取**长效设备 Token**（90 天滑动过期，可服务端吊销），App 持久化于安全存储
- "我的设备"页：列出该账号已授权设备（名称/时间），可吊销其他设备
- 登出 = 本地清除 + 服务端吊销当前 Token
- **验收**：登录成功率、错误密码提示与网页一致；吊销后 App 下次请求 401 → 引导重新登录；
  Token 不出现在日志/截屏

### FR-2 相册自动备份（P0 · 灵魂功能）
- 默认**仅备份照片**（jpg/png/heic/heif…），**视频为开关默认关**（已与用户确认）
- 备份目标：`incoming/<用户名>/手机相册/`（与网页直传一致，家人都能看到归属）
- 触发：连 Wi-Fi 后周期扫描（默认 15 分钟）+ 系统媒体库变更即时感知（平台支持时）
- 约束开关（默认开）：仅 Wi-Fi、充电时；跑在系统后台任务框架上（Android WorkManager /
  iOS BGTaskScheduler），系统杀掉后自动重生
- 去重：本地账本记录 `(媒体库 ID, 修改时间)`；服务端秒传指纹优先（现有 sha256 协议）
- 进度可见：备份页显示"已备份 N 张 / 待备份 M 张 / 最近备份时间"；失败项可手动重试
- 新备份完成发本地通知（可关）
- **验收**：100 张照片冷启动备份全程无人工干预；杀进程/重启手机后自动恢复；
  断网中断后续传不重传已成功部分；飞行模式下不尝试
- 边界：相册中被删除的照片**不会**从网盘删除（单向备份，明确提示用户）

### FR-3 照片浏览（P0）
- 时间线瀑布流（按月分组，对应 `/api/photos` + facets）
- 点开大图查看（捏合缩放、左右切换、信息面板：拍摄时间/尺寸/上传者）
- 下载原图/保存到系统相册
- **验收**：253 张量级滚动流畅（缩略图懒加载，占位微光同网页版）

### FR-4 文件浏览（P1）
- 目录树浏览（网格/列表）、新建文件夹、重命名、删除（进服务端回收站）
- 文件预览：图片/视频（系统播放器）/文本/PDF（系统查看器）
- 下载到 App 沙盒并可直接"用其他应用打开"

### FR-5 传输中心（P0）
- 上传/下载队列统一展示：进度、速度、剩余时间、暂停/续传/取消/重试
- 分块续传协议全量对齐网页（init→chunk→finish，自适应分片，秒传）
- 应用被杀后重启，未完成队列恢复续传
- **验收**：500MB 视频上传中途杀 App → 重开 → 从断点继续且服务端校验通过

### FR-6 系统分享接收（P1）
- 系统分享面板中出现"LAN Share"→ 接收单/多文件 → 落 `incoming/<用户>/分享暂存/`
- 接收后立即可选：改目标目录 / 创建对外分享

### FR-7 分享管理（P1）
- 我创建的分享列表（状态徽章/过期时间/下载次数）
- 快速创建：选文件 → 有效期/提取码/下载上限/定向成员（调取成员列表）
- 撤销分享；复制链接（局域网/公网双地址）
- **验收**：与网页版分享管理页能力对齐（创建/撤销/复制）

### FR-8 通知（P2）
- 未读数角标 + 通知列表（对应 `/api/notifications`），打开即全部已读
- 轮询策略：前台 60s / 后台 1h（与 PWA 一致的起步方案）
- 定向分享到达 → 本地通知

### FR-9 设置（P0 精简版）
- 服务器地址（自动记忆；LAN/公网多地址可切换）
- 自动备份：开关/仅 Wi-Fi/充电时/视频开关/查看备份账本
- 主题：跟随系统/浅/深；语言首版仅中文
- 已用空间展示（`/api/disk`）

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | LAN 首屏照片墙 <2s（温缓存 <1s）；500MB 上传烤机无发热异常（前台服务通知常驻） |
| 安全 | Token 存系统安全存储（Android Keystore / iOS Keychain）；流量全 HTTPS；自签证书按 §设计文档"信任策略"处理；不上传任何数据给第三方 |
| 可靠 | 上传幂等（服务端 SHA256 校验兜底）；本地账本与服务端对账 |
| 兼容 | Android 8.0+（覆盖小米主流机型）；iOS 13+ |
| 隐私 | 不采集任何统计/埋点；相册仅读取（不写入）；隐私政策文案随上架准备 |
| 合规 | 上架商店（P2）：软著/隐私政策/备案按商店要求补齐；首版 Android 走 APK 直装分发 |

## 6. 发布与分发

1. **首版**：Android APK 经 LAN Share 自身分享链接分发到家庭群（吃自己的狗粮）
2. **P2**：小米/华为商店上架（需软著+隐私政策+iOS 需 $99/年 开发者账号）

## 7. 验收总纲

- 全部 P0 验收点通过 + 网页版回归 70 项不受影响（后端改动仅新增，不破坏既有契约）
- 双端（Android 真机小米 + 模拟器；iOS 模拟器）各跑一遍 P0 清单
- 自动备份连续运行 72 小时无崩溃、无重复上传（账本对账）
